# 姿态系统：内部 S³ 流形 + 用户友好接口 + 连续性缝合

引擎姿态（旋转）系统的核心架构决策，基于 SO(3) 的拓扑性质（毛球定理：SO(3) 无法被任意 3 参数全局光滑参数化）。

## 决策

1. **内部姿态存储永远在 S³（单位四元数）上**：`Transform::rotation` 必须是单位四元数（随时保证 ||q||=1），禁止裸欧拉角作为内部状态。
2. **用户输入/输出用局部坐标**：欧拉角、方向向量（lookAt）、FromTo 旋转等只出现在边界层（用户/脚本/编辑器），进入系统即转 S³。
3. **所有插值在 S³ 上沿测地线**：动画/相机/网络重建用 slerp（最短路径），不降维到欧拉角空间。
4. **奇点处理靠连续性约束层自动修复**：动画导入时欧拉关键帧序列 → S³ 符号连续性缝合（q 与 -q 选最近）；网络 3 分量重建时用上一帧连续性选 w 符号。
5. **物理模拟在 S³ 切空间（so(3) 坐标）积分**：角速度 ω 是切空间向量，用指数映射 `q(t+dt) = exp(0.5·ω·dt) ⊗ q(t)` 或归一化投影法积分，避免欧拉角变化率在奇点发散。
6. **position/scale 不受流形约束**：姿态流形只约束 rotation 分量；position/scale 走常规 R³ 线性代数。

## 理由（背景推导）

- 三维旋转群 SO(3) 是 3 维流形，但任意连续 3 参数参数化必然有拓扑奇点（万向锁）——欧拉角在 pitch=±90° 退化。
- 单位四元数集合 = S³（4D 单位球面），是 SO(3) 的双覆盖，无奇点，且其上测地线插值（slerp）= 旋转最短路径。
- 角速度 ω 是切空间 so(3) 的坐标，3 分量永远良好定义，不像欧拉角变化率会在奇点发散。

## 边界（不做什么）

- 不引入"在欧拉角上打补丁"的方案作为内部表示。
- 四元数不用于反射/镜像（det=-1 变换，需反射矩阵，见 M6）。
- 网络丢包场景：3 分量重建依赖连续性，需增量编码 + 周期全量帧兜底（见设计文档）。
